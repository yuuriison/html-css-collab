# Collab 04. CSS, selektory, dziedziczenie i kaskada — Tech

## Pojęcia potrzebne teraz

### CSS

- Struktura plecenia w CSS składa się z:
    - selektora 
    - bloku deklaracji: 

```
.note { color: navy; } 
```

-  Selektor wskazuje elementy, właściwość mówi co zmienić, wartość — jak. 
- Klasa HTML `class="card featured"` oznacza dwie klasy
    - selektory to `.card` i `.featured`
- Typy selektorów:
    -  `p` wybiera akapity (czyli to co będzie w tagu `<p>`)
    -  `.card p` akapity wewnątrz kart
    -  `.card > p` tylko bezpośrednie dzieci
    -  `#id` identyfikator konkretnego taga w kodzie (do stylowania w collabie używamy głównie klas)

- Style mogą być osadzone:

    - na stronie w sekcji `<head>` (wpisane z tzw. palca)
    - bezpośrednio w danym tagu w kodzie HTML
    - załączone z pliku

- Arkusz styli z pliku podłączamy w `<head>`

     ```
     <link rel="stylesheet" href="assets/css/base.css">
     ```

- style umieszczone bezpośrednio w tagu będą miały pierwszeństwo przed stylami załączanymi

    - kaskada rozstrzyga sprzeczne deklaracje

    - w naszych zwykłych regułach autora, bez warstw, !important, stylów inline i animacji, porównujemy specyficzność: 

        ```
        #ID > klasy/atrybuty/pseudoklasy > typy
        ```

    - przy remisie wygrywa późniejsza deklaracja.
        - to uproszczenie dla tego zakresu, a nie pełny algorytm kaskady

- dziedziczenie przenosi niektóre właściwości, np. `color` i `font-family`, z rodzica na dzieci. 
    - `padding` nie jest dziedziczony!

- kolor może być zapisany jako:
    -  nazwa (np. `red`, `navy`)
    - hex (np. `#0F0F0F`) 
    - rgb() (np. `rgb(255, 241, 231)
    - nie trzeba znać wszystkich formatów - są od tego narzędzia online i w IDE

## Przykład spoza projektu wydarzenia

```html
<main class="lesson">
  <h1>Poradnik ogrodnika</h1>
  <p class="note">Podlewaj rano.</p>
  <p>Sprawdź wilgotność gleby.</p>
</main>
```

CSS do powyższego przykładu (w arkuszu podłączonym w head):

```css
body { color: #202b3c; background: #f5f7fb; font-family: system-ui, sans-serif; }
p { color: #253858; }
.note { color: #7a2600; }
.note { color: #174b37; }
```

## Do stworzenia

## Sprawdź zrozumienie

Q: Czy późniejsza reguła zawsze wygrywa?
A: Nie. 

Q: Czy class można powtarzać w dokumencie?
A: Tak.

Q: Czy id ma być unikalne w dokumencie?
Tak.

## Typowe problemy

- brak kropki w selektorze klasy
- brak średnika między deklaracjami
- nadmierna specyficzność; 
- stylowanie wszystkich `<p>` zamiast konkretnego komponentu
- zmiana wyłącznie w DevTools
